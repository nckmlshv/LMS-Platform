# Kafka Topic `reviews.events` → Сервис «Уведомления»

Спецификация обработки сообщений из топика `reviews.events` в сервисе «Уведомления».

## Назначение

Отправка уведомления автору курса о создании нового отзыва на его курс в системе LMS.

## Источник сообщений

| Параметр         | Значение                              |
| ---------------- | ------------------------------------- |
| Брокер           | Kafka                                 |
| Топик            | `reviews.events`                      |
| Продюсер         | Сервис «Отзывы»                       |
| Консюмер         | Сервис «Уведомления»                  |
| Формат сообщения | Protobuf |

## Входные данные

Ссылка на контракт Kafka: https://github.com/nckmlshv/LMS-Platform/blob/main/Kafka%20Users.Reviews%20Topic.proto

Список полей:

| Поле        | Тип данных             | Обязательное | Ограничения / Описание                                                  |
| ----------- | ---------------------- | ------------ | ----------------------------------------------------------------------- |
| event_id    | string                 | Да           | UUID, уникальный идентификатор события            |
| type        | ReviewEventType (enum) | Да           | UNSPECIFIED / REVIEW_CREATED / REVIEW_UPDATED / REVIEW_DELETED          |
| event_time  | Timestamp              | Да           | Время возникновения события (UTC)                                       |
| review_id   | string                 | Да           | UUID отзыва                                                             |
| user_id     | string                 | Да           | UUID автора отзыва                                           |
| text        | string                 | Нет          | Текст отзыва, до 1000 символов                                          |
| pics_urls   | repeated string        | Нет          | Список URL прикреплённых изображений                                    |
| created_at  | Timestamp              | Да           | Дата и время создания отзыва (UTC)                                      |
| updated_at  | Timestamp              | Нет          | Дата и время последнего обновления отзыва (UTC)                         |

## Исходящие данные

При успешной обработке события `REVIEW_CREATED` сервис «Уведомления» формирует email-уведомление автору курса.

| Поле         | Тип данных | Обязательное | Описание                                                          |
| ------------ | ---------- | ------------ | ----------------------------------------------------------------- |
| recipient_id | string     | Да           | ID автора курса (получатель уведомления)                          |
| channel      | string     | Да           | Канал доставки: `email`                                           |
| subject      | string     | Да           | Тема письма                                                       |
| body         | string     | Да           | Тело письма (текст отзыва, имя автора отзыва, ссылка на курс)     |
| review_id    | string     | Да           | ID отзыва, по которому отправляется уведомление                   |

### Пример сформированного уведомления

```json
{
  "recipient_id": "c9d8e7f6-1a2b-3c4d-5e6f-7a8b9c0d1e2f",
  "channel": "email",
  "subject": "Новый отзыв на ваш курс «Машинное обучение»,
  "body": "Студент Donald Trump оставил отзыв: «Отличный курс, всё понятно объясняют!»",
  "review_id": "a3f2d1b4-7c8e-49a0-9b3c-5e6f7a8b9c0d"
}
```

## Алгоритм работы сервиса «Уведомления»

1. Получение сообщения из топика `reviews.events`.
2. Десериализация сообщения по схеме `ReviewEvent`:
   - Сообщение не удалось десериализовать → Отправить в Dead Letter Queue (`reviews.events.dlq`), закоммитить offset, прекратить выполнение
   - Сообщение успешно десериализовано → Продолжить выполнение
3. Проверка идемпотентности:
   1. Поиск совпадений в БД по полю `event_id`
      - БД вернула запись (событие уже обработано) → Закоммитить offset, прекратить выполнение
      - БД не вернула записи → Продолжить выполнение
4. Валидация данных:
   1. Проверить поля сообщения на соответствие типов данных и ограничений
      - Хотя бы одно из обязательных полей не валидно → Отправить в DLQ, закоммитить offset, прекратить выполнение
      - Поля валидны → Продолжить выполнение
5. Маршрутизация по типу события:
   - `type == REVIEW_CREATED` → Перейти к шагу 6
   - `type == REVIEW_UPDATED` → Закоммитить offset, прекратить выполнение
   - `type == REVIEW_DELETED` → Закоммитить offset, прекратить выполнение
   - `type == UNSPECIFIED` или неизвестный тип → Отправить в DLQ, закоммитить offset, прекратить выполнение
6. Получение данных о курсе и его авторе:
   1. Запрос в сервис «Курсы» для получения `course_id` и `author_id` по `review_id`
      - Сервис не ответил / вернул ошибку → Повторить попытку (retry с экспоненциальной задержкой), при исчерпании попыток отправить в DLQ
      - Курс не найден → Отправить в DLQ, закоммитить offset, прекратить выполнение
      - Сервис вернул данные → Продолжить выполнение
7. Получение данных автора курса:
   1. Запрос в сервис «Пользователи» по `author_id` для получения email  
8. Получение данных автора отзыва:
   1. Запрос в сервис «Пользователи» по `user_id` для получения имени студента
9. Формирование и отправка email через провайдера рассылки.
10. Сохранить `event_id` в БД обработанных событий.
11. Отправить уведомление получателю
12. Закоммитить offset в Kafka.

## Гарантии доставки

| Параметр          | Значение                                  |
| ----------------- | ----------------------------------------- |
| Гарантия          | At-least-once                             |
| Идемпотентность   | По полю `event_id`                        |
| Стратегия retry   | Экспоненциальная задержка, до 5 попыток   |
